## Aislamiento y preparación

Se creó el proyecto Compose independiente `trueca-chatbot-staging`, con una base
PostgreSQL nueva, secretos y volúmenes propios. No se copió el `.env` operativo:
se extrajo únicamente la clave OpenAI existente a un archivo temporal privado.
La clave y la salida a Internet estuvieron disponibles solo para el evaluador CLI.
No se levantaron el servidor web ni el proxy de staging ni se publicaron puertos.

El preflight verificó imágenes por digest, AMD64, redes y volúmenes independientes.
`check_chatbot_staging` comprobó identidad de base y usuario, sesiones separadas,
manifiesto de migraciones y durabilidad (`fsync=on`, `synchronous_commit=on`). Tras
revisar `migrate --plan`, se aplicaron todas las migraciones pendientes únicamente a
la base nueva, incluidas las tres de chatbot. `check_chatbot_staging --ready` confirmó
que no quedaban migraciones pendientes.

Se cargaron las doce FAQ sintéticas referenciadas por el dataset, un centro sintético
y una categoría sintética. El instalador puntual rechazaba una base no vacía y no
utilizó el instalador destructivo de fixtures de tests. Las fuentes quedaron fijas
durante ambas modalidades. Incluyen casos adversariales y una FAQ no publicada para
comprobar filtros; **sus condiciones y el horario sintético no son información municipal
verificada**. No se importaron conversaciones, usuarios ni otros datos operativos.

## Corrección posterior de idioma y formato (solo pruebas simuladas)

Tras el piloto se corrigieron en el repositorio los dos pendientes observados. Los
resultados reales anteriores y la candidata por digest permanecen intactos; no se
efectuaron nuevas llamadas ni se reconstruyó o desplegó la candidata.

- `response_style.py` obtiene del idioma activo y de la petición las restricciones de
  presentación, y comprueba idioma y exactamente tres frases en la respuesta generada.
- La selección extractiva conserva su evidencia literal y admite `display_text` para
  localizar FAQ descriptivas o distribuir su información en tres frases. El mismo
  request genera esa presentación; no hay llamada de traducción ni reparación adicional.
- Grounded exige texto visible en el idioma activo, con citas en el idioma original.
  Para tres frases se solicitan tres claims de una frase o una abstención vacía.
- Se mantienen la revalidación pública, las rutas locales y los bloqueos de claims.
  Las unidades críticas siguen exigiendo texto literal: no se habilitan traducciones
  generadas de reglas. Un fallo de idioma/formato se maneja de forma recuperable,
  libera la cuota y no se reenvía al repetir el mismo identificador de solicitud.
- El mock genérico no inventa traducciones ni frases adicionales; puede abstenerse.
  Los casos de presentación se verifican con respuestas explícitas del SDK simulado.
